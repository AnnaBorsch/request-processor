# Request Processor

Микросервис для приема запросов на отправку уведомлений, обеспечивающий гарантированную доставку сообщений в Kafka с помощью паттерна Transactional Outbox.

## Технологический стек

- **Java 21**
- **Spring Boot 3.5.x**
- **Apache Kafka**
- **PostgreSQL**
- **Maven**
- **Lombok**

## Функциональность

1.  **REST API (`/api/v1/notifications`)**
    *   Принимает POST-запросы с телом: `{"type": "SMS|EMAIL|PUSH|TG_MESSAGE", "message": "string"}`.
2.  **Паттерн "Стратегия" (Strategy)**
    *   В зависимости от значения поля `type` выбирается соответствующий обработчик (`SmsHandler`, `EmailHandler`, `PushHandler`, `TelegramHandler`).
    *   Каждый обработчик подготавливает данные для отправки в свой топик Kafka.
3.  **Гарантированная доставка (Transactional Outbox)**
    *   При получении запроса данные не отправляются в Kafka напрямую, а сохраняются в таблицу `notification_outbox` в рамках той же транзакции БД.
    *   Это гарантирует, что сообщение не будет потеряно в случае сбоя Kafka до сохранения в БД.
4.  **Шедулер (Scheduler)**
    *   Периодически (с настраиваемой задержкой `delay-ms`) опрашивает таблицу `outbox`.
    *   Забирает пачку (`batch-size`) неотправленных (`sent = false`) сообщений и отправляет их в Kafka.
    *   В случае успеха помечает сообщение как отправленное (`sent = true`). При ошибке увеличивает счетчик попыток (`attempt`).
